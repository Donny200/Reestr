# Административное управление услугами

Реализовано 24.09.2026. Страница: `/admin/functions`. Ветка: `codex/admin-functions-ui`.
После обновления backend перезагрузите страницу, чтобы заново получить пользователя и словари интерфейса.

## Что работает

- Права из login и `GET /api/auth/me`, Context API, `hasPermission`, динамическое меню и защита маршрутов.
- Таблица всех доступных статусов, фильтры организации/категории, поиск, языки и страницы по 50 записей.
- Создание DRAFT с обязательными названием, описанием, организацией и исходным языком.
- Защищённый редактор, предпросмотр, индикатор несохранённых изменений, ошибки без потери введённого текста.
- Отправка на проверку, возврат с причиной, публикация, деактивация, повторная проверка и история.
- Редактирование переводов одного языка с сохранением остальных языков и их источников.
- Опциональный Azure-автоперевод с повторной попыткой; отсутствие ключа не ломает ручной редактор.

## Решения по неоднозначностям задания

1. Расширен существующий UserResponse, используемый login/me. Добавлены permissions и организации с id/name.
   Прежние organizationIds и названия ролей ROLE_* сохранены. Права берутся из роли, не из отдельного списка.
2. Сохранён GET /api/functions/admin под FUNCTIONS_VIEW. У него нет параметров фильтрации из примера,
   поэтому фильтрация и пагинация выполняются на клиенте. Меню видно при любом праве раздела;
   для чтения административных карточек по-прежнему требуется FUNCTIONS_VIEW.
3. В запросе создания используется настоящий organizationId, не orgFunctionId.
   Восьми непривязанным черновикам перед проверкой нужно назначить и сохранить существующую организацию.
   Новые организации автоматически не создаются.
4. Основные поля редактируются под FUNCTIONS_EDIT. FUNCTIONS_CREATE не расширяет защиту существующего PUT.
   Для сотрудников только с FUNCTIONS_MANAGE_REQUIREMENTS сохранена отдельная форма требований и прежний endpoint.
5. Публикация требует FUNCTIONS_PUBLISH; возврат — FUNCTIONS_REVIEW.
   Деактивация использует прежний DELETE /api/functions/{id} под FUNCTIONS_DEACTIVATE, без физического удаления.
6. В интерфейсе правки разрешены только в DRAFT. DEACTIVATED доступен для чтения.
   Путь к правкам: повторная проверка → возврат рецензентом в DRAFT.
   Прежние backend-методы, допускавшие редактирование DEACTIVATED, не ужесточались.
7. Название и описание используют существующие JSONB-карты nameTranslations/descriptionTranslations.
   Второе хранилище localizedText не создавалось. Требования остаются строкой на исходном языке.
8. Добавлен sourceLanguage в сущность и DTO. Миграция устанавливает en для трёх прежних карточек
   и ru для восьми идентифицированных редакционных сидов.
   Изменение оригинала обновляет его языковую копию и сбрасывает машинные переводы соответствующих полей.
   Другие ручные переводы сохраняются; интерфейс напоминает проверить их актуальность.
9. Французский включён, поскольку он реально активен наряду с en/ru/uz.
   Подписи нового раздела добавлены в существующие таблицы reference-service на четырёх языках.
   Для отсутствующего перевода карточки показывается оригинал с пояснением.
10. Добавлены только отсутствовавшие API:
    - GET /api/functions/{id}/admin: любой статус, FUNCTIONS_VIEW и проверка организации.
    - PUT /api/functions/{id}/translations/{language}: один язык, FUNCTIONS_EDIT + FUNCTIONS_TRANSLATIONS_EDIT.
      Прежний PUT, заменяющий всю карту переводов, сохранён без изменения контракта.
    - GET /api/functions/translation-capabilities: только признак доступности, без ключей.
    - POST /api/functions/{id}/translate: тело {languages: string[], overwriteMachine: boolean}.
      Только DRAFT, оба права редактирования переводов и проверка организации.
11. Автоперевод использует существующий TranslationClient. После создания заполняются отсутствующие языки,
    если конфигурация и права позволяют; английский исходный язык также поддержан.
    Ручные переводы не перезаписываются. Запросы Azure выполняются вне транзакции БД.
    Перед сохранением повторно проверяются версия, статус и организация; ошибки не оставляют частичных переводов.
    401 от Azure преобразуется в ошибку внешнего сервиса, чтобы не разлогинивать пользователя.
12. Публичные React-страницы не менялись; публичные API продолжают отдавать только PUBLISHED.
    Дата изменения не показывается, поскольку такого поля в ответе нет.
    Старый административный адрес /admin/functions/{id}/edit ведёт в новый редактор.
    Новые permissions не добавлялись, существующие назначения прав не расширялись.
13. Ручной перевод отмечен галочкой и подписью «Ручной». Эта отметка не означает отдельное прохождение ревью.

## Проверки

До реализации прошли исходные mvn test, TypeScript и frontend build.

| Проверка | Результат |
| --- | --- |
| Корневой mvn -B test, пять модулей | 219 тестов: 106 identity, 24 reference, 89 catalog; без ошибок и пропусков |
| npm test | 9 браузерных сценариев Chromium |
| npm run typecheck | Успешно |
| npm run lint | Успешно, без предупреждений |
| npm run build | Успешно |
| AdminFunctionsBrowserIT | React/Chromium → реальный Spring HTTP/JWT → временная PostgreSQL |

UI-проверки охватывают список и пагинацию, RU/UZ и fallback FR, ошибки/повтор создания,
редакционный цикл с причиной возврата, права на кнопки и маршруты, ручные переводы,
ошибку/повтор автоперевода и отдельное право на требования.

Сквозной тест создаёт карточку, сохраняет RU/UZ-переводы, перечитывает её, публикует,
проверяет присутствие в публичном API, деактивирует и проверяет исчезновение.
Проверяются ограничение списка организацией и реальные 403 на чтение/изменение чужой карточки.
JUnit после браузера отдельно проверяет строки и аудит в PostgreSQL.
В успешном сценарии не было ошибок JavaScript/console.error.

Identity/reference в браузерном тесте представлены контролируемыми ответами.
Функции, JWT-проверки, транзакции, миграции и сохранение работают на настоящем function-catalog-service.
Azure проверен тестовыми ответами клиента, включая отказ/таймаут и конфликт с параллельным решением рецензента.
Это не проверка внешнего Azure с рабочим ключом.

Повторный запуск:

```sh
mvn -B test
cd front
npm ci
npx playwright install chromium
npm test
npm run typecheck
npm run lint
npm run build
cd ..
mvn -B -pl function-catalog-service -Dtest=AdminFunctionsBrowserIT test
```

Docker требуется для PostgreSQL-тестов. AdminFunctionsBrowserIT запускается отдельно,
чтобы обычный Maven-прогон не требовал Node/Chromium. Все тестовые записи находятся во временных контейнерах.

## Ограничения

AZURE_TRANSLATOR_ENDPOINT, AZURE_TRANSLATOR_KEY и AZURE_TRANSLATOR_REGION в рабочем контейнере пусты.
Внешний автоперевод недоступен; можно заполнить переводы вручную.
Отсутствующие переводы старых карточек не выдуманы и не помечены фиктивно как machine.
Для изменения перевода опубликованную карточку нужно вернуть в DRAFT через редакционный процесс.

npm audit обнаружил ранее существующую dev-зависимость js-yaml 4.3.1 с advisory GHSA-2883-xcg3-v3hh.
Она не добавлена этой задачей; обновление посторонних зависимостей здесь не выполнялось.

Изменения сохранены отдельными локальными коммитами. Push не выполнялся.
Изначально присутствовавшие незакоммиченные security-тесты пользователя не изменялись и в коммиты задачи не включались.

# Аналитика организации и качество карточек

Модуль помогает сотрудникам организации следить за своими карточками услуг: сколько карточек в каждом статусе,
какие требуют исправления, какие сообщения посетителей ждут обработки и насколько посетители интересуются информацией в каталоге.

Сайт публикует только информацию об услугах и не принимает заявления.
Показатели активности — это анонимные просмотры страниц каталога и переходы по ссылкам.
Они не означают заявления, клиентов или оказанные услуги. Эта оговорка показана на панели и в описании API.

## Что найдено в проекте и какие решения приняты

- Сообщения посетителей уже хранились в `information_reports` в `function_catalog_db`, аудит — в `audit_logs`.
  Модуль расширяет эту систему, второй системы сообщений нет.
- Расписание проверки взято из существующей модели: карточка требует повторной проверки через 180 дней (`VerificationStatus.RECHECK_AFTER`)
  или после изменения ключевых полей (`verification_outdated`). Новое расписание не вводилось.
- Обязательные поля взяты из редактора карточки: название, описание и организация. Необязательные поля не проверяются.
- Активные языки берутся из `GET /api/languages` identity-service, тем же списком пользуется интерфейс.
- Внутреннего сервиса уведомлений нет, поэтому напоминания показываются в интерфейсе. Почта, SMS и новые секреты не используются.
- Библиотеки графиков в проекте нет. График построен на SVG без новых зависимостей.
- Ограничение частоты и определение клиента повторяют приём сообщений: заголовок `X-Real-IP` от Nginx,
  в памяти только SHA-256 адреса с солью процесса.
- Агрегаты хранятся с ключом `UNIQUE NULLS NOT DISTINCT`, поэтому нужен PostgreSQL 15 или новее. В проекте используется PostgreSQL 16.

## Права и роли

| Право | Новое | Что даёт |
|---|---|---|
| `ORG_ANALYTICS_VIEW` (категория `Analytics`) | да | Панель организации, активность, очередь качества, напоминания и их выгрузки |
| `ORG_REPORTS_MANAGE` (категория `Reports`) | да | Просмотр сообщений своей организации, смена статуса, контакт посетителя |
| `REPORTS_VIEW` | нет | Просмотр сообщений и их выгрузка без контакта посетителя |
| `REPORTS_MANAGE` | нет | Вместе с `REPORTS_VIEW` сохраняет прежнее право менять статус |

- `SUPER_ADMIN` получает все права существующим механизмом инициализации.
- `ORG_ADMIN` получает `ORG_ANALYTICS_VIEW` и `ORG_REPORTS_MANAGE` только при первой инициализации роли, как и остальные права по умолчанию.
  В существующих установках роль автоматически не расширяется. Права назначает супер-администратор на странице «Роли».
- `MODERATOR` не меняется и остаётся с `ORGANIZATIONS_VIEW` и `REPORTS_VIEW`.
- Существующие права не переименованы, не удалены и не ослаблены.

Ограничение по организации выполняет бэкенд. Список организаций берётся из JWT.
Параметр `organizationId` только сужает выборку до одной из своих организаций, чужая организация даёт 403.
Доступ ко всем организациям есть только у `SUPER_ADMIN` и у держателей существующего `FUNCTIONS_MANAGE_ANY_ORGANIZATION`.
Скрытие элементов во фронтенде не является защитой.

## API

| Метод и путь | Доступ |
|---|---|
| `POST /api/analytics/events` | Анонимно, с ограничением частоты. Тело: `type`, `serviceId` или `organizationId`. Ответ 202 |
| `GET /api/analytics/summary?organizationId=&categoryId=&from=&to=` | `ORG_ANALYTICS_VIEW` |
| `GET /api/analytics/engagement?organizationId=&categoryId=&from=&to=&granularity=AUTO\|DAY\|WEEK` | `ORG_ANALYTICS_VIEW` |
| `GET /api/analytics/engagement/export?…&breakdown=SERVICES\|DAILY&delimiter=COMMA\|SEMICOLON` | `ORG_ANALYTICS_VIEW` |
| `GET /api/analytics/quality-queue?organizationId=&categoryId=&issue=&status=` | `ORG_ANALYTICS_VIEW` |
| `GET /api/analytics/quality-queue/export?…&delimiter=` | `ORG_ANALYTICS_VIEW` |
| `GET /api/analytics/reminders?organizationId=&categoryId=` | `ORG_ANALYTICS_VIEW`. Ответ: `total` и до 200 самых новых напоминаний в `items` |
| `POST /api/analytics/reminders/{id}/acknowledge` | `ORG_ANALYTICS_VIEW` и организация напоминания. Ответ 204 |
| `GET /api/reports?status=&category=&entityType=&entityId=&serviceCategoryId=&from=&to=&organizationId=` | `REPORTS_VIEW` или `ORG_REPORTS_MANAGE` |
| `GET /api/reports/{id}`, `GET /api/reports/{id}/history` | `REPORTS_VIEW` или `ORG_REPORTS_MANAGE` и организация сообщения |
| `PUT /api/reports/{id}/status` с телом `{status, note}` | `ORG_REPORTS_MANAGE` или `REPORTS_VIEW` + `REPORTS_MANAGE` и организация сообщения |
| `GET /api/reports/export?…&delimiter=` | `REPORTS_VIEW` или `ORG_REPORTS_MANAGE` |

Даты передаются как `YYYY-MM-DD`. Ошибки: 400 при неверных параметрах (для отклонения без пояснения — `fieldErrors.note`),
403 для чужой организации или без права, 404 для неизвестного объекта, 409 для недопустимого перехода статуса, 429 с `Retry-After`.
Маршрут `/api/analytics/**` добавлен в шлюз рядом с `/api/functions/**` и `/api/reports/**`.

## Определения

**Период.** Календарные дни по времени Ташкента (UTC+5), обе границы включены.
По умолчанию это последние 30 дней, включая сегодня. Наибольший период — 366 дней.
Предыдущий период имеет ту же длину и заканчивается за день до начала выбранного: для 1–10 марта это 19–28 февраля.
Изменение считается как (текущее − предыдущее) / предыдущее и округляется до целого процента.
Если в предыдущем периоде событий не было, процент не показывается.

**События активности.**

| Событие | Что считается |
|---|---|
| `CATALOG_VIEW` | Открытие главной страницы каталога со списком услуг. С `organizationId` — открытие страницы организации со списком её услуг |
| `SERVICE_VIEW` | Открытие публичной страницы опубликованной услуги |
| `OFFICIAL_LINK_CLICK` | Нажатие на ссылку «Официальный источник» на странице услуги или организации |
| `PHONE_CLICK` | Нажатие на номер телефона в блоке контактов |
| `MAP_CLICK` | Нажатие на ссылку OpenStreetMap или на собственную ссылку на карту |
| `PRINT` | Печать страницы услуги кнопкой или средствами браузера (событие `beforeprint`) |

Не считаются: вошедшие сотрудники (фронтенд не отправляет событие, бэкенд игнорирует запросы с токеном),
административные страницы, браузеры с Do Not Track или Global Privacy Control, повтор того же просмотра в той же вкладке за 30 минут,
повтор того же нажатия за 10 секунд, события по неопубликованным карточкам и организациям без опубликованных услуг,
запросы сверх лимитов (120 на клиента за 10 минут и 20 000 в час на весь сервис).

Организация события по услуге берётся из сохранённой карточки на момент события. Переданный клиентом `organizationId` для услуг игнорируется.
Если карточку позже перевели в другую организацию, прошлые агрегаты остаются за прежней организацией.
Фильтр по категории оставляет только события по услугам и использует текущую категорию карточки.
Просмотры каталога и страниц организаций при выбранной категории не учитываются.

**Самые просматриваемые услуги.** До 10 услуг с наибольшим `SERVICE_VIEW` за период. При равенстве выше та,
у которой больше действий (сумма трёх видов нажатий и печати).

**Динамика.** До 62 дней включительно — по дням, дольше — по неделям с понедельника по воскресенье, крайние недели обрезаются границами периода.

**Состояние карточек.** Текущее число карточек каждого статуса в выбранных организациях и категории. Период на эти числа не влияет.

**Очередь качества.** Деактивированные карточки в очередь не попадают.

| Проблема | Условие |
|---|---|
| `VERIFICATION_OVERDUE` | Опубликованная карточка не проверялась, последняя проверка старше 180 дней или карточка изменилась после проверки |
| `SOURCE_MISSING` | Ссылка на официальный источник пуста или не является адресом http(s) с хостом |
| `INFORMATION_INCOMPLETE` | Пусто название, описание или не назначена организация |
| `TRANSLATIONS_MISSING` | Для активного языка, кроме исходного языка карточки, нет перевода названия, описания (если оно есть) или заполненного поля инструкции |

Если список языков недоступен, проверка переводов пропускается, а панель и очередь сообщают об этом.
Каждая строка очереди говорит, что исправить, и ведёт в нужный раздел редактора (`#function-details`, `#function-translations`, `#function-verification`).
Сотрудник без права просмотра карточек видит пояснение вместо ссылки.

**Сообщения на панели.** «Не решены» — сообщения `NEW` и `IN_PROGRESS` сейчас. «Получено за период» — по дате получения в днях Ташкента
со сравнением с предыдущим периодом. Фильтр по категории оставляет сообщения об услугах этой категории, сообщения об организациях при этом не учитываются.

## Сообщения посетителей

| Из статуса | Допустимые переходы |
|---|---|
| `NEW` | `IN_PROGRESS`, `RESOLVED`, `REJECTED` |
| `IN_PROGRESS` | `RESOLVED`, `REJECTED` |
| `RESOLVED`, `REJECTED` | `IN_PROGRESS` (повторное открытие) |

- Для `REJECTED` пояснение обязательно, для остальных переходов необязательно. Недопустимый переход возвращает 409 со списком допустимых.
- Каждая смена статуса пишется в `audit_logs` (`REPORT_STATUS_CHANGE`): кто, когда, переход и пояснение. История видна в карточке сообщения.
- Изменение карточки услуги не закрывает сообщение. Карточка сообщения лишь предупреждает, что услуга менялась после его получения.
- Контакт посетителя видят только сотрудники, которые обрабатывают сообщения. Сотрудник с одним `REPORTS_VIEW` видит лишь отметку, что контакт оставлен.
  Контакт удаляется при закрытии сообщения и не попадает в выгрузку.
- Если карточку перевели в другую организацию, её сообщения переходят вместе с ней.
- Анонимная отправка не изменилась.
- Миграция `V4__report_workflow_statuses.sql` переводит `IN_REVIEW` в `IN_PROGRESS` и `DISMISSED` в `REJECTED` без удаления строк.

## Напоминания

- Ежедневная проверка (через 2 минуты после запуска, затем каждые 24 часа) создаёт одно открытое напоминание на пару «карточка + проблема».
  Это гарантирует частичный уникальный индекс `quality_reminders_open_issue_idx`.
- Открытие панели напоминания не создаёт. Панель показывает общее число напоминаний, первые 10 и кнопку для остальных (до 200).
- Когда проблема исчезает, напоминание закрывается. Напоминание о переводах не закрывается, пока список языков недоступен.
- «Принять к сведению» скрывает напоминание для всей организации на 14 дней и записывает, кто и когда это сделал.
  Если проблема осталась, напоминание появляется снова.
- Карточки без организации пропускаются, потому что напоминать некому.
- При нескольких экземплярах сервиса одновременные проверки могут столкнуться на уникальном индексе.
  Такая проверка пишет предупреждение в журнал, следующая проверка всё досчитает.

## Выгрузки CSV

- UTF-8 с BOM, строки через CRLF, кавычки по RFC 4180.
- Ячейки, которые начинаются с `=`, `+`, `-`, `@`, табуляции, перевода каретки или их полноширинных вариантов, начинаются с апострофа,
  чтобы табличный редактор не выполнил их как формулу.
- Разделитель — запятая или точка с запятой. Фронтенд выбирает точку с запятой, если язык браузера использует десятичную запятую, как ожидает Excel в таких локалях.
- Время указано по Ташкенту в формате `yyyy-MM-dd HH:mm:ss`, заголовки колонок на английском.
- Выгрузка сообщений ограничена 10 000 строками. Если строк больше, ответ содержит `X-Export-Truncated: true`, и интерфейс предлагает сузить фильтры.
- Выгрузки используют те же сервисы, проверки прав и ограничения по организации, что и экраны.

## Приватность и хранение

- Посетителю не нужен вход. Имена, e-mail, учётные записи, отпечатки устройств и cookie для аналитики не используются.
- В базе хранятся только счётчики по дню, типу события, организации и карточке. Записей о посетителях нет.
- IP-адрес не сохраняется. Ограничитель частоты держит в памяти соль процесса и SHA-256 адреса до конца окна.
- Повторы отсекаются в `sessionStorage` вкладки (`reestr-engagement-recent`). Эти данные не отправляются на сервер и исчезают при закрытии вкладки.
- Агрегаты хранятся 730 дней и удаляются ежедневной задачей.

| Настройка | По умолчанию |
|---|---|
| `catalog.analytics.zone` | `Asia/Tashkent` |
| `catalog.analytics.retention` | `730d` |
| `catalog.analytics.default-period-days`, `max-period-days` | `30`, `366` |
| `catalog.analytics.per-client-limit`, `per-client-window` | `120`, `10m` |
| `catalog.analytics.global-limit`, `global-window` | `20000`, `1h` |
| `catalog.reminders.renotify-after` | `14d` |
| `catalog.reminders.scan-initial-delay`, `scan-interval` | `PT2M`, `PT24H` |
| `catalog.scheduling.enabled` | `true` (в тестах `false`) |

## Ограничения

- Активность не показывает, подал ли посетитель заявление и получил ли услугу.
- Числа приблизительные: блокировщики, Do Not Track и отключённый JavaScript уменьшают их, а несколько вкладок одного человека увеличивают.
  Посетители за одним адресом делят лимит частоты. Скрипт может накрутить счётчики только в пределах лимитов.
- Лимиты частоты хранятся в памяти каждого экземпляра сервиса.
- Доверие к `X-Real-IP` держится на Nginx. Порт шлюза 8082 не следует открывать в production.
- Проверка переводов зависит от identity-service, список языков кэшируется на 5 минут.
- Очередь качества считается в памяти при каждом запросе. Для каталога в тысячи карточек этого достаточно.
- Напоминания видны только в интерфейсе.
